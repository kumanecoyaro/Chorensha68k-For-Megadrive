# 超連射68k (ver1.10) 解析メモ

対象: `CH68_110_1.xdf` 内 `CRS68K/SZ2.X`（Human68k .X 実行形式）。
アドレスはすべて SZ2.X をベースアドレス 0 でロードしたときの値。
逆アセンブルリストは `make disasm XDF=...` で `build/SZ2.lst` に生成される
（`tools/dis68.py`: capstone ベースの再帰下降逆アセンブラ。DOS/IOCS コール名、
X68000 I/O レジスタ名、リロケーション情報からのラベル付けを行う）。

## 1. ファイル構成

| ファイル | 内容 |
|---|---|
| `SZ2.X` | 本体。text $3C104 / data $DEB0 / bss $48C56、エントリ $398FC（XC ランタイム）→ `main` = $3892 |
| `assets.tgz` | 本体が miniz で展開して読む素材（`XSP_DAT/*`, `PCM_DAT/*`） |
| `XSP_DAT/*.sp, *.xsp` | 16x16 PCG（128 バイト/枚、4bpp、8x8 ブロックを 左上→左下→右上→右下 の順） |
| `XSP_DAT/*.ref, *.frm` | XSP 複合スプライト。ref = {枚数.w, frm オフセット.l}、frm = {dx.w, dy.w, PCG.w, 属性.w}（dx,dy は直前のスプライトからの相対） |
| `map.chp` | 32x32 ドットの「チップ」256 個。ヘッダ 8 バイト + 4x4 個の BG ワード（bit15 V反転, bit14 H反転, bit8-11 パレット, bit0-7 パターン） |
| `map.bg0 / map.bg1` | ヘッダ 16 バイト（幅 8, 高さ $400）+ チップ番号バイト列。8 チップ = 256 ドット幅 × 1024 行 |
| `bg_pcg.sp` | BG 用 8x8 パターン 256 個 |
| `bg_*.pal` | グラフィック画面用 256 色パレット（GRB555+I）。ステージ1は `bg_fb_nw.pal` を使用 |
| `SZ_PALET.pal` | スプライト用 16 パレット × 16 色 |

## 2. メインループ（$38A2 内 L03A50〜）

1 フレームの処理順:

1. `fn_04338` ステージ進行（ステージ番号で `fn_06de4`(ST1), `fn_077b6`(ST2) ... へ分岐）、ランク $4A0C8 を 128 フレーム毎に +1
2. `fn_2cbda` 垂直同期待ち
3. `fn_05e50` 自機
4. `fn_06470` 自機ショット
5. `fn_04094` 全オブジェクト更新（連結リスト、各オブジェクトの +$24 の関数を呼ぶ）
6. 入力をリプレイバッファに記録、`fn_2cf3a` XSP スプライト出力
7. `fn_056ae` BG スクロール

乱数 `fn_345c8` は 1024 語の乱数テーブルを順に引くだけ（リプレイ互換のため）。
`fn_2fb06` は atan2（0=上, $40=右, $80=下）。三角関数表 `D_3e3bc` は
[速度 0..31][角度 0..255] の (dx, dy) 表（1/64 ドット単位、速度 1 で半径 64）。

## 3. 座標系

* オブジェクト座標は 16bit、1/64 ドット単位。XSP にはそのまま `>>6` して渡すので、
  16x16 セルの左上の画面座標は `(v>>6) - 16`、複合スプライトの中心は `(v>>6) - 8`。
* X68000 の画面は 256x256。自機の可動範囲は X: $400〜$4000, Y: $400〜$3F00。

## 4. オブジェクト

* プール $180 個 × $80 バイト、`fn_040b6` で確保、`fn_0410e` で解放（+$1A/+$1E 双方向リスト）。
* クラス表 `D_46460`: 16 バイト × $250 種 = {毎フレーム処理.l, 生成関数.l, 得点.l, 耐久力.w, …}。
  生成関数には呼び出し側スタック上の $80 バイトの「テンプレート」(x, y, 属性, 角度 +$54, 速度 +$64 …) を渡す。
* 主なフィールド: +0 x, +2 y, +4 パターン(ref 番号), +6 属性(パレット/反転), +8/+A 当たり判定半径(ドット),
  +$16 基本パターン, +$22 型, +$24 処理関数, +$3C/+$3E 速度, +$4C/+$4E カウンタ, +$54 向き, +$5C 耐久力, +$78 タイマ。
* ref 番号は XSP ファイルを読み込んだ順の通し番号（title=0, bullet32=1.., … player=$ABD, player2=$AC9, zako=$AD5, obj204_d, parts32, obj1a0, obj200=$B18 …）。

## 5. 自機 `fn_05e50`

* 入力はテンキー方向 1〜9 → 角度表 `D_489ea` → 速度 1 の三角関数表 × (速度 $30>>4 = 3)。
* 傾き $9048E: 左右入力で ±1/フレーム（±8 まで）、パターン = $ABD + ((傾き/8)+1)*2 + ((フレーム>>1)&1)。
* 出現: x=$2200, y=$5400、タイマ $5939A=$100。$80 までは毎フレーム y-=$40 で自動上昇、0 まで無敵（パレット点滅）。

## 6. 自機ショット `fn_06470`（超連射）

* ボタンの押下エッジを数え、タイマ $90496 が空いていれば 12 フレームの発射シーケンスを開始。
  押しっぱなしでは連射しない（連打前提）。
* タイマ & マスク(レベル0: 3) が 0 のフレームで発射:
  * タイマ≦7 なら中央弾: y-$100 から vy=$FD00（-12 ドット/F）、威力 = パワー×2
  * 左右一対の拡散弾: x±($200 + (タイマbit1?$100:0))、角度 = タイマ&~3、速度 9、威力 = パワー
* パワーレベル表 `D_489a6`（6 語 × 5 段階）。弾は 30 発のプール（y=0 が空き）。

## 8. 敵

### 型 $190 ザコ（init `fn_131d4` / 処理 L13298, zako.ref 16 方向）
* 出現時に自機方向の X 速度の半分を vx に、vy=$C0+乱数(0..63)。毎フレーム vy-=2（減速して上へ戻る）。
* 8 フレーム毎に向き $54 を ±16 ずつ目標へ回転（下降中は自機方向、上昇中は上）。
  向きが合っていて 16 フレーム毎・下降中・カウンタ < $20+ランク/4 なら型 $130 弾を発射（自機方向±乱数、速度 $30）。
* 被弾で即破壊、得点 250。

### 型 $1F0 中型機（init `fn_16fc0` / 処理 L170DC, obj200.ref #0, 128x80）
* y=-32 ドットから出現、耐久力 640、当たり判定 ±32x±24。
* タイマの下位 8 ビットが $60〜$E0 の間は停止、それ以外は 1 ドット/F で降下。sin/cos でゆらゆら揺れる。
* (t&$E7)=$80 で 3way 弾（型 $134, 間隔 8, 速度 $38）を左右 2 方向に、(t&$E7)=$A0 で大型弾（型 $132, 速度 $40）。
* 撃破で大爆発、得点 1000、アイテム（型 $1F8, 未移植）。

### 敵弾
* 速度ベクトル表 $4B91E = 速度16の三角関数表 × 設定値($10) / 256（`fn_05170`）、弾速度 × 表 >> 4。
* 自機との当たり: 型 $130 ±2x±4、$134 ±3x±5、$132 ±4x±6 ドット。

## 9. BG（`fn_05574`, `fn_056ae`, `fn_301f6`）

* BG は X68000 の BG 面ではなく、256 色グラフィック画面 2 ページにソフトウェアで描画している。
  チップ 1 個 = 4x4 タイル、各 8x8 タイルを展開表 `$305BE` で 1 ドット 1 ワード (パレット*16+色) に変換して書き込む。
* レイヤ 0 = map.bg0（手前、透過あり、初速 -$400 = 4 ドット/F）、レイヤ 1 = map.bg1（奥、-$100 = 1 ドット/F）。
  位置は 24.8 固定小数、速度は目標値へ 1/256 ずつ近づく。
* マップ行カウンタは減少方向に進み、`loop_end`($9046A) に達すると `loop_start`($90472) に戻る。
  ステージ開始時 `fn_05906((stage-1)*8, $10)` → ステージ1は行 1008〜1023 をループ、状態 $110 で行 766 付近まで進む。
* 4 ラインごとに 1 チップずつ描画して負荷を分散している。

## 10. 効果音

* `PCM_DAT/SZ2_PCM.CNF` に PCM 番号 → ファイル / STAT / PR の対応がある。STAT は IOCS `_ADPCMOUT` の d1
  （上位バイト = サンプリングレート: 4 = 15.625 kHz, 3 = 10.416 kHz、下位 = パン）。
* `fn_034ae(番号)`: そのフレームの要求より PR が低ければ無視、以上なら置き換え（B_8401a）。
* 使用例: 自機ショット $20、ザコ爆発 $01、中型機爆発 $03、ショット命中 $42、自機被弾 $28 / $29。

## 11. BGM（MDX → YM2612 + DCSG）

* `BGM_DAT/SZ2_BGM.CNF` は MDC（MCDRV 形式）を指すが、同じ曲の MDX が `BGM_DAT/original` にあるのでそちらを使う。
  13 曲、各 16 トラック（PCM8 拡張形式）だが、使われているのは FM の A〜H の 8 トラックのみ（ADPCM トラックは空）。
* ほぼ全チャンネルにデチューン約 -128（-2 半音、±10 程度ずらしてコーラス）が掛かっている。
  X68000 の OPM は 4 MHz 駆動（標準 3.58 MHz より約 +1.92 半音高い）なので、その補正。
  MD 版はノート番号 n を MIDI n+15 として YM2612 / DCSG の周波数を計算し、デチューン込みで X68000 実機と ±8 セントで一致する。
* 繰り返し: $F6 n 00 で開始（2 バイト目は実行時カウンタ）、$F5 の相対オフセットは $F6 直後を指す。
  $F4（最終回で脱出）の相対オフセットは対応する $F5 のオペランドを指すので、脱出先はそこから 2 バイト先
  （以前これを誤って $F5 のオペランド $FF をテンポ命令として実行し、1 面の曲が 55 秒付近から崩れていた）。
* $F7（&）は「次の音符の終わりでキーオフしない」。その次の音符はキーオンせず音程だけ変える（スラー / タイ）。
  q8 は次の音符（または休符）の直前までキーオフしない。
* @v は減衰量（0 が最大音量、実データは 0〜17）。v0〜15 は MXDRV の音量表で TL 加算値に変換。
* ソフトウェア LFO（MP / MA）のパラメータは 1 ティックあたりの変化量（1/256 単位）。
* チャンネル割り当て（`tools/convert_bgm.py` が曲ごとに決定）: ノイズ（OPM レジスタ $0F / $ED）を使うチャンネル、
  他チャンネルの遅延コピー（エコー）、音域の高いチャンネルを優先して 2ch を外す（DCSG へ回す経路もドライバに
  残してあるが現在は未使用）。
* YM2612 の $A4-$A6（ブロック / F ナンバー上位）は全チャンネル共通のラッチで、続く $A0-$A2 の書き込みで確定する。
  必ず $A4 → $A0 の対で書くこと（片方を省略すると他チャンネルの値で鳴る）。
* YM2612 はレジスタ / DAC 書き込みの後しばらくビジーになり、その間の書き込みは失われることがあるので、
  Z80 は毎回ステータスのビジービットを待ってから書く。
* レジスタの重複書き込み省略では「未書き込み」を値と別に管理すること（以前は 0xFF を初期値にしていて、
  D1L/RR=$FF のような値が書かれずに残った）。
* DAC は FM6 のパン（$B6）を共有するので、効果音の再生中は中央に固定し、終了時に BGM の値へ戻す。
* 演奏はティック単位（Timer-B 値 → 1 フレームあたりのティック数表）で、VBlank の実回数で進める。
* YM2612 への書き込みは Z80 がキュー経由で行う（DAC へのサンプル書き込みとアドレスラッチを奪い合わないため）。

## 12. 原作コードの直接実行（tools/relocate.py）

ゲームロジックは手で移植せず、SZ2.X の 68000 コードを MD 上でそのまま動かしている。

* メモリ: .X のリロケーション表（全絶対アドレスの位置）を書き換えて、text / data → ROM $10000 + a、
  使用する BSS 範囲 → RAM $FF0000〜 に詰めて配置。BSS の使用範囲はリロケーション先を関数ごとに集計して決めた
  （グローバル変数・自機ショット・オブジェクトプール $49FB4〜、ステージ / 自機状態 $5931E〜、
  BG / ショット状態 $90252〜 ほか）。XSP 作業領域・リプレイバッファ・GVRAM 描画用マップ展開領域などは不要。
* オブジェクトプールは 383 個 → 128 個（`fn_04034` の個数を書き換え、RAM 16 KB）。
* data 部で書き込まれる変数: クラス $40 の処理関数（`fn_044a2` がステージ毎に設定）、パレットアニメ状態。
* text 部に状態を持つライブラリ: 当たり判定（`fn_2f3cc`〜`fn_2f704`、グリッド $2F722 と矩形 $2F822 を
  PC 相対で参照）、乱数（`fn_345c8`、インデックス $345E0）。ルーチンごと RAM へコピーして使う。
* 範囲の終端アドレスを指すリロケーションは別シンボルの先頭（例: $2F922 = `fn_2f922`）なので、
  範囲外として扱うこと（範囲の「1 つ後」を同じ範囲に含めると誤動作する）。
* マップ（B_8C252、2 層 × $2000）は ROM 上の map.bg0/bg1 を直接参照させる（`fn_053ba` のヘッダ解釈結果
  = 幅マスク 7、高さマスク $3FF、行シフト 3 をフックで設定）。
* フック（関数先頭 6 バイトを `jmp HOOK_BASE+6*i` に書き換え）:
  XSP（`fn_2c9fe` xsp_set, `fn_2ca2c`, `fn_2ca5e` xobj_set; `fn_2ca5a` は movem して `fn_2ca5e` へ
  落ちるので原作のまま）、垂直同期 `fn_2cbda`、XSP 出力 `fn_2cf3a`、IOCS 入力（`fn_39dac` BITSNS,
  `fn_39e16`/`fn_39e58`/`fn_39e7a` JOYGET）、リプレイ入出力（`fn_00f26` 方向, `fn_01048` ボタン）、
  パレット（`fn_05224`, `fn_05a3a`, `fn_051b8`）、BG（`fn_053ba` 読み込み, `fn_301f6`/`fn_303a2` チップ描画）、
  テキスト（`fn_2f06a` 1 文字, `fn_2f2aa` 消去）、音（`fn_034ae` 効果音要求, `fn_03590` BGM, `fn_03872` フェード）、
  ゲームオーバー後の `fn_0132c`（ネームエントリ等）ほか。
* XC のレジスタ規約は d0-d2/a0-a2 破壊、gcc は d0/d1/a0/a1 破壊なので、C から原作関数を呼ぶ時は
  `ocall`（d2-d7/a2-a6 を保存）を通す。レジスタ渡しの XSP 関数のフックは原作が保存するレジスタを全部保存する。
* 起動: タイトルメニュー（`fn_02dac`）は通さず、`L03e60` の初期値設定と「ゲームスタート」分岐を C で再現して
  `fn_038a2`（1 ゲーム分のメインループ）を呼ぶ。

## 13. スプライト（XSP の置き換え）

* PCG 番号は全 .sp / .xsp を読み込んだ順の通し番号（sz2_main.sp, rot32.sp, rot16.sp, debris.sp, mob.sp,
  title.xsp, bullet32.xsp, …）。ref 番号も .ref の読み込み順の通し番号で、frm の PCG 番号には直前に読んだ
  PCG ファイルの先頭番号が足される（ele_arc は rot32 の $50、debris1 は debris.sp の $C4 を明示指定）。
* info: bit15 V 反転、bit14 H 反転、bit11-8 パレット、bit5-0 優先度（大きいほど手前）。xobj_set の info は
  各 frm の info と XOR される。座標は 1/64 ドット、XSP のスプライト座標 (16,16) が画面左上。
* 変換: PCG 1 枚 = MD の 2x2 スプライト（X68000 の PCG と同じタイル順・同じ 4bpp 形式なのでそのまま）。
  frm が 2 枚以上の ref は合成して 32x32 までのブロックに切り直す（大型機 1 機 40 枚 → 十数枚、
  ザコ・自機オプション・砲台パーツ・大型弾など 32x32 に収まるものは 16x16 x 4 枚 → 1 枚）。
  反転を多用する爆発・破片・衝撃波は合成すると ROM が 2 MB を超えるため、PCG 単位のまま VDP の反転を使う。
* VRAM: 4 タイル枠 160 個 + 16 タイル枠 30 個のキャッシュ。（ブロック, パレット）をキーにハッシュ表で管理し、
  未登録ならパレット変換表を通してステージングバッファへ展開、VBlank で DMA。
* パレット: X68000 のスプライトパレット 16 本を、使用頻度で重み付けした k-means で MD の 2 本へ割り当て、
  1 バイト（2 ドット）単位の変換表で色番号を付け替える。
* テキスト: SZ_TEXT.pcg は 1 文字 4 プレーン（プレーン p は +$20*p、各 8 行 2 バイト間隔）。
  テキストパレットは `fn_051b8` が _TPALET2 でパレットファイルの 33〜47 色（= スプライトパレット 2）を
  設定するので、フォントはスプライトパレット 2 の変換表で MD パレットへ割り当てる。
* 削減: 爆発の数は原作のまま（生成も描画も間引かない）。爆発用の枠（FX_MAX = 28 枚）を画面上の爆発の数で
  均等に分け、どの爆発も必ず描く。敵の爆発（expl4、PCG 単位のスプライト）は、そのフレームの枚数が
  自分の取り分に収まれば全部（少ないときは原作どおり）、収まらなければ PCG を 1 枚おきに描く。
  （32x32 への合成は、コマごとに最大 2.4 KB の VRAM 転送が要り、同時 3 個以上で破綻するので不採用）
  パーティクル（敵破壊時に飛び散るパーツ = クラス $81〜$83 の debris.sp、火花・破片 = クラス $122〜$124）は
  生成を常に拒否し、spark / debris1 / debris2 の ref と debris.sp の PCG も描画しない。
* リプレイ: 削除。記録・再生の入力関数（`fn_00f26` / `fn_01048`）はパッドを直接読み、
  記録開始・終了（`fn_00f06` / `fn_01036` / `fn_00c9c`）は何もしない。リプレイバッファ（$61ffc〜）は RAM に置かない。

## 13b. BG（1 枚化）

* 原作は 2 枚のグラフィック画面に近景（map.bg0）と遠景（map.bg1）を描き、別々の速度で縦スクロール
  （1 面: 近景 4 px / フレーム、遠景 1 px / フレーム。スクロール処理 `fn_056ae`、全面描画 `fn_05574`）。
* MD 版は Plane B 1 枚に重ねて描き、近景の速度で一緒に動かす（Plane A は大型の敵用に空ける）。
  * 遠景のチップ描画はページ上の位置を覚えるだけ。近景のチップ描画時に、その行の下に来る遠景の行
    （原作でその瞬間その位置に見える行を、遠景の模様の周期の倍数だけずらして行ごとに連続させる）を選んで合成。
  * 近景のタイルは不透明 1748 / 空 188 / 半透明 96。空は遠景のタイル、半透明は遠景チップとの合成タイル
    （変換時に作成、1 面で 1429 枚。2 つの BG パレットのうち合う方）を参照カウント付きの VRAM プールに読み込んで使う。
  * `fn_056ae` は同じチップの再描画を省くので無効化（$057f0）、全面描画のあとは全セルを合成し直す（`x_bg_full`）。

## 13c. 大型の敵を Plane A に（`src/plane.c`）

* 1 面の蟹型（obj202: 左半身 $B1E・右半身 $B1F・中央 $B20 の 3 ref、半身は中央から左右対称に 0〜4 px 開閉、
  2 機同時もある）とボス（obj204 $B29）。ボス戦中は他の敵が出ないので、VRAM の敵領域（タイル 1364〜1523）を共用。
* `tools/convert_sprites.py` が原作どおりに重ねた 1 枚絵を作る（蟹は開き 0 px と 4 px の 2 枚: 0〜2 px は前者、
  3〜4 px は後者で近似。タイルは蟹 158 / ボス 140）。
* フレームの終わりに XSP 呼び出しから探し、絵のタイルが VRAM にあればその呼び出しをスプライトから外して
  Plane A に表示（ボス優先、蟹は表示中のものに一番近い 1 機）。初回はタイルを数 VBlank で転送、その間はスプライト。
* 被弾フラッシュ（別パレット）の部分はスプライトのまま上に重ねる。Plane A は画面と同じ幅なので、
  左右の端にかかる列は折り返さないよう空白にする（端で最大 7 px 欠ける）。
* 大きいエフェクト（自機のボム: 優先度 $3F の expl2 / expl3 / flare、ボス撃破の特殊爆発: expl2 の $B8 / $B9、
  flare）も Plane A に描く。スプライト用のブロックと VRAM キャッシュをそのまま使い、ブロックのタイルを
  その下のセルに置く（位置は Plane A の 8 px 格子に丸める）。敵の絵より手前、全スプライトより奥。
  1 フレームに読み込むタイル（1.5 KB）と 16 タイル枠（12 個）に上限を設け、スプライトの分を残す。
* 取り消した呼び出しは部品 0 個の ref（spr.h `REF_EMPTY`）に付け替える。
* VRAM: 合成 BG タイルのプール 96 枚は H32 で使わない領域（ウィンドウ面の 2 行目以降、スプライト表の 65 個目以降、
  全画面スクロール表の残り）に置き、スプライトキャッシュは 4 タイル枠 128 + 16 タイル枠 28。

## 14. 処理時間

* 1 フレーム（262 ライン）の内訳（通常の場面）: 原作ロジック 約 80 ライン、スプライト展開 約 80 ライン、
  VBlank 割り込み（表示更新 7 + 音楽・効果音 40）。原作の X68000 は 55.5 Hz、MD は 59.9 Hz。

  同じ音色・同じ音量の再設定は書き込まない。
